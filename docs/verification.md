# 검증 기록

검증일: 2026-10-22, Asia/Seoul. Node.js 26.0.0, npm 11.12.1. 테스트와 빌드는 로컬에서 실행했습니다.

## 자동 검사

- `npm run typecheck`: TypeScript strict 검사 성공.
- `npm test`: fake-indexeddb 기반 동작 테스트 30개 통과.
- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 성공.
- `npm audit`: 알려진 의존성 취약점 0건 (검증 당시).
- `node scripts/verify-history.mjs`: 최초 241개 커밋의 날짜별 수, +09:00 작성자 시간대, 빈 커밋 부재 검증.

테스트는 제목·설명·태그 및 복합 검색, 대소문자, 카테고리, 관련 태그 순위, 파일 MIME·크기, 텍스트 길이, URL 프로토콜, 태그 중복 제거, 초기화 반복, 보드 이름 검증·변경, 중복 저장·다중 보드 저장, 없는 데이터 거부, 저장 해제, 보드 삭제 시 원본 보존, Blob 보존, 핀 수정·관계 정리, 샘플 삭제 거부, 저장 공간 오류 메시지를 다룹니다.

## 브라우저 사용 흐름

로컬 Chromium 기반 브라우저에서 다음을 직접 확인했습니다.

1. 검색창에서 `커피` 입력 → URL 검색어 반영 → 일치하는 핀 2개 → 상세 화면.
2. 상세에서 새 보드 생성과 저장 → 새로고침 → 저장한 보드 링크와 핀 유지.
3. 보드 이름 변경 → 새 이름 표시 → 보드 삭제 후 원본 핀 유지.
4. JPEG 업로드 → 미리보기 → 제목·설명·태그 입력 → 생성 → 새로고침 후 Blob 이미지 로드 확인 → 수정 → 테스트 핀 삭제.
5. 저장 창에서 Esc 닫기 → 원래 저장 버튼으로 포커스 복원. 네이티브 dialog 사용.
6. 홈 추가 로딩 18 → 36개, 자연 카테고리 선택 시 URL 반영 및 24개 결과.
7. 이미지 확대 모달, 검색 결과 없음 안내, 없는 핀 주소의 복귀 링크.
8. 샘플 이미지 파일을 일시적으로 사용할 수 없게 하여 이미지 실패 안내 확인 후 파일 복원.
9. 저장 작업에 `QuotaExceededError`를 일시 주입하여 모달 내부 오류 안내와 미저장 상태 확인 후 코드 복원. 실제 디스크를 채우는 방식은 사용하지 않았습니다.
10. 320·390px 모바일, 768px 태블릿, 1440px 데스크톱 CSS viewport에서 레이아웃 검수. 390px 2열, 768px 3열, 1440px 5열과 가로 넘침 부재 확인.

## 범위와 한계

Safari·Firefox 및 실제 모바일 기기 검수는 수행하지 않았습니다. 대용량 사진의 브라우저별 저장 한도는 환경에 따라 다릅니다. 데이터의 서버 백업·기기간 동기화는 없습니다. 외부 사진 출처 링크와 Google Fonts는 네트워크가 필요하지만 앱의 샘플 이미지 파일은 로컬에 포함됩니다. GitHub 기여 그래프의 갱신 시점은 GitHub에 따릅니다.
